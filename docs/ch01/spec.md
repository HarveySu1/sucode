# sucode · Phase 1 规格 —— 终端对话内核

> 状态：已与需求方澄清定稿（2026-10-15）
> 本文档只回答「做什么、不做什么、什么算完成」。实现细节（函数名/参数/默认值/错误文案/阈值）一律不写，散见于 tasks.md（实现指引）与 checklist.md（验收值）。

## 1. 背景

sucode 是一个用 Python 开发的终端 AI 编程助手（对标 Claude Code），最终形态是能在终端里通过对话完成编码任务的 Coding Agent。但 Agent 能力（工具调用、文件读写、代码编辑）必须建立在可靠的对话内核之上。Phase 1 只做这个内核：启动进入界面 → 提问 → 流式看到回答 → 记得上文 → 换个模型继续聊。

## 2. 目标用户

- 主要：项目作者本人，Windows PowerShell 日常使用，偶用 macOS/Linux
- 次要：借鉴本项目学习 Coding Agent 架构的 Python 开发者

## 3. 能力清单

- C1. 在终端执行 `sucode` 后进入全屏 TUI 对话界面
- C2. 底部为多行输入框：Enter 发送，Shift+Enter 换行，支持粘贴多行文本
- C3. AI 回复流式逐字呈现，不等待完整生成
- C4. 回复按 Markdown 渲染，代码块有高亮
- C5. 多轮对话，AI 记住本会话内之前说过的内容
- C6. 思考过程以暗淡样式流式展示于正文之前：Anthropic 端为 extended thinking（开关与预算在配置中控制）；OpenAI 兼容端为 reasoning_content 字段（如 deepseek-reasoner，随模型自带，无预算控制，2026-10-17 增补）
- C7. 支持 Anthropic 与 OpenAI 两种 API 协议后端，通过配置切换
- C8. 任意 OpenAI 兼容端点（DeepSeek/GLM/Qwen 等）可通过 OpenAI 协议 + 自定义地址接入
- C9. 单个 YAML 配置文件管理多套 profile（协议/模型/地址/密钥），命令行参数选择 profile，文件内指定缺省 profile
- C10. 对话过程中可通过命令切换 profile，切换后对话历史保留、可继续追问
- C11. 内置命令：退出、清空上下文重新开始、查看帮助、切换/查看 profile
- C12. 生成过程中可按键中断，已生成部分保留在对话中并带中断标记
- C13. 密钥可从环境变量读取（配置留空时自动回退）
- C14. 配置缺失或非法时启动失败，给出可照抄的示例配置与修复指引
- C15. 请求失败（网络/鉴权/超上下文）时界面呈现可读错误，程序不崩溃

## 4. 非功能要求

- N1. Python 3.10+；Windows PowerShell 为一等公民（中文不乱码），macOS/Linux 常见终端可用
- N2. 流式体验：生成期间界面不卡顿、不闪烁，可随时中断
- N3. 架构：Provider 层抽象为统一接口，新增一种 API 后端不改动 TUI 层与会话层
- N4. 依赖克制：仅 TUI、Markdown 渲染、两家官方 SDK、YAML 解析四类依赖
- N5. 密钥安全：密钥仅存在于本地配置与环境变量，不出现在任何界面与日志输出中

## 5. 设计骨架

```
┌────────────────────────────────────────────────┐
│ TUI 层（Textual 全屏应用）                        │
│   布局：顶栏(profile/模型) · 滚动对话区 · 多行输入  │
│   职责：输入、命令、中断、流式渲染、错误展示          │
├────────────────────────────────────────────────┤
│ 会话层                                          │
│   职责：内存对话历史、上下文组装、profile 热切换      │
├────────────────────────────────────────────────┤
│ Provider 层（统一流式对话接口）                    │
│   ├─ Anthropic 实现（透出 thinking 事件）          │
│   └─ OpenAI 实现（含任意兼容端点）                 │
├────────────────────────────────────────────────┤
│ 配置层                                          │
│   职责：YAML 多 profile 的加载与校验               │
└────────────────────────────────────────────────┘
```

依赖方向：上层依赖下层，禁止跨层（TUI 不直接 import SDK；会话层不知道具体协议）。
新增后端 = 新增一个 Provider 实现 + 配置里加一个 profile，其他层不动。

## 6. Out of Scope（本期明确不做）

- O1. 工具调用 / 文件读写 / 代码编辑 / Shell 执行（Agent 能力，Phase 2+）
- O2. 会话持久化与恢复（退出即清空）
- O3. 上下文窗口管理（自动截断/压缩），超限只报错并提示清空命令
- O4. token 用量与成本统计展示
- O5. system prompt 定制
- O6. OpenAI 端思考的预算控制与开关参数（协议不提供该机制；思考内容展示本身见 C6，2026-10-17 修订）
- O7. 一次性非交互模式（`sucode "问题"` 直接出结果）
- O8. 配置交互式向导、HTTP 代理设置、多模态输入
- O9. 跨会话记忆 / RAG / 联网搜索

## 7. 完成定义

Phase 1 完成当且仅当：checklist.md 全部条目实际操作通过（含两条硬性要求：端到端验收必须是真实 API 非 mock；两个协议后端各完成一次 ≥3 轮的多轮对话）。
