## I. 权限确认（脚本验证 + 真实 API，C51 修订新增）

## 承接值（spec 砍掉的具体值，全部以此为准）

### 并发与上限
- 安全批并发上限：**4**（信号量）
- 工具轮数硬上限：**10**（沿用 ch02）；心跳间隔 **2.0s**（沿用 ch02）

### 计划文件
- 默认路径：**plan.md**（cwd 下）；`/plan <相对或绝对路径>` 可指定，当次会话内生效

### 普通模式系统提示词（最小文案）
```
你是 sucode，一个运行在终端里的 AI 编程助手。优先借助工具获取真实信息再回答；回答用中文，保持简洁。不要在回复正文里输出思考或推理过程（如自我权衡、计划独白），正文只写面向用户的结论与必要说明。
```

### 计划模式系统提示词
```
Plan mode is active. 你不能执行任何修改操作，不能编辑文件、不能提交代码、不能修改配置。
唯一可以写入的文件是下面指定的 plan file：{plan_file_path}

你的工作流程：
1. 用 ReadFile、Grep、Glob、Bash（只读命令）探索代码
2. 分析用户需求，设计实现方案
3. 把计划写入 plan file
4. 等待用户确认后再执行
```

### Bash 只读白名单（并发判定与计划拦截共享）
- 命令集：`ls`、`dir`、`Get-ChildItem`、`cat`、`type`、`Get-Content`、`pwd`、`Get-Location`、`tree`、`where`、`git status`、`git diff`、`git log`、`git show`、`git branch`
- 排除元字符（出现即不安全 / 拦截）：`|` `;` `>` `<` `&`
- 首部命令不在白名单 → 不安全（如 `python`、`rm`、`npm`、`pip`）

### 拦截提示文案（is_error 结构化结果，回传模型）
- 写类：「计划模式：写操作已拦截（仅允许写入计划文件 {plan_file_path}）。请继续用只读工具探索，或把计划写入计划文件。」
- 命令类：「计划模式：该命令不在只读白名单内，已拦截。请改用只读命令（如 ls、cat、git status/diff/log）。」

### 终止事件原因枚举
- `completed`（正常完成）/ `interrupted`（用户中断）/ `cancelled`（取消信号）/ `error`（错误）/ `max_rounds`（达轮数上限）

### 权限确认（C51）
- 确认范围：category == **write** 恒确认；category == **command** 且不在只读白名单确认；read 与白名单命令不确认
- 等待应答超时：**60 秒**，超时按拒绝
- 拒绝文案（is_error 结构化结果回传模型）：**「用户拒绝了本次工具执行，未运行。」**
- 应答三值：`allow` / `deny` / `always`；always = **本会话内该工具名不再询问**（`/new` 不清除，重启失效）
- TUI 确认提示形态：`⚠ 请求执行 {工具名}\n{参数摘要}\n允许吗？输入 y 允许 / n 拒绝 / a 本会话内总是允许（60 秒无应答自动拒绝）`
- 应答词表：`y`/`yes` → allow；`n`/`no` → deny；`a`/`always` → always
- 计划模式不走确认（保持自动拦截 / 放行规则）

### 项目记忆提取（C52）
- 触发周期：每 **5** 次编排运行（全部终止原因均计数）；空历史不触发
- 记忆文件：工作目录下 **project_memory.md**，追加式（`## YYYY-MM-DD HH:MM` 段落 + 条目行）
- 提取提示词：从对话历史提炼项目规则 / 工程约定 / 技术约束 / 用户偏好，每条一行 `- ` 开头，无内容输出「（无）」
- 不注入系统提示词（O22）；不去重不合并（L11）；失败静默（fire-and-forget）
